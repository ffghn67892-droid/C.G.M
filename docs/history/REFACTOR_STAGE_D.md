# D단계 — KARDS 규칙 카탈로그

2026-09-18 완료. E1(MTGA)은 별도 승인 대기.

## 적용 내용

KARDS의 일일 퀘스트, 무료 카드, 주간 상자를 `ruleCatalog`의 `quest`·`claim`으로 연결했다. 기본 50/60 GOLD, 3개 보관, 패스 추가 공급, 완료 항목 다음 갱신 제거, 상자 티어별 희귀도, 상자 아래 접힌 누적 목록을 유지한다.

최초 설정에서 규칙을 먼저 확인·편집하며 퀘스트·무료 보상을 추가할 수 있다. 등록 후에는 탭 상단 **퀘스트·보상 규칙**에서 같은 편집기를 사용한다. 매일/매주/N일, KST 시각, 생성 수·상한·패스 추가 수, 보상 묶음, 퀘스트별 허용 보상을 설정한다. 사용자가 추가한 규칙은 삭제할 수 있으며 기존 원장은 삭제하지 않는다. 기본 규칙 3개는 호환성 때문에 삭제할 수 없다.

보상 수량 입력은 `골드:50, 카드:1` 형식이다. 알려진 재화 이름은 기존 내부 키로 변환하고 새 재화 이름도 지원한다. 퀘스트별 보상 선택은 체크박스로 지정한다. 최초 설정에서는 보상 종류마다 이번 회차의 기수령 횟수를 입력할 수 있다. 기존 초기 진행도 입력과 중복해 입력하면 안 되며 합계가 회차 상한을 초과하면 확정을 거부한다.

## 실제 선언 형식과 책임

`game.ruleCatalog`는 규칙 배열이다. 각 규칙은 다음을 가진다.

- `id`, `type`, `label`, `source`
- `schedule`: `kind`, `time`, 주간의 `weekday` 또는 N일의 `days`·`anchor`
- `spawnCount`, `capacity`, `passExtra`
- `rewards`: `{id, label, resources: {재화키: 수량}}` 배열
- `quests`: `{id, label, rewardIds}` 배열 (`quest` 유형)

계획서의 `rewardTypes`/`reset` 예시는 실제 구현에서 `rewards`/`schedule`로 통일했다. 유형별 정책은 현재 완료 유지·다음 갱신 제거로 고정한다. `goal`·자원·패스 등의 후속 유형은 아직 구현하지 않았으며 해당 게임 이관 시 추가한다.

`game-config.js`: 기본 카탈로그, 검증, 주기 계산, 보유 상태 동기화, 보상 확정. `game-extras.js`: 카탈로그 기반 목록과 공통 버튼 연결. `setup.js`: 규칙 편집·초기 기수령 보상·미리보기. `app.js`의 KARDS 전용 렌더링과 갱신 본문은 호출 연결로 축소했다. 설치 파일 목록을 수정하지 않도록 현재 로딩 중인 영역별 파일에 배치했다.

## 보존·실패 처리

- 저장 키와 v2 유지. 기존 KARDS 진행 필드와 원장 키를 어댑터로 사용한다.
- 보유 퀘스트에 허용 보상 사본을 저장한다. 보상 수정은 새로 생성한 퀘스트부터 적용한다. 완료 기록은 당시 보상 사본을 유지한다.
- 주기 변경은 현재 회차를 새 주기에 맞춰 설정하며 수령 횟수와 보유 항목을 유지한다. 편집만으로 추가 보상을 지급하지 않는다.
- 상한을 낮춰도 기존 퀘스트를 잘라내지 않는다. 새 생성만 상한으로 제한한다.
- 생성·완료·보상은 규칙 ID와 항목 ID로 검증한다. 지난 회차에서 눌린 완료 요청, 중복 지급, 잘못된 보상 참조는 거부한다.
- KARDS 동작 실패 시 해당 게임 사본을 복원한다. 성공 이후의 화면 갱신은 저장 실패 처리와 분리했다.
- 규칙 기반 상태 표시·갱신 알림·상단 갱신 시각을 연결했다.
