# D 보완 — 범용 구성 기반 전환

2026-09-18 완료. 사용자의 “적용해봐” 승인으로 진행했다. E1은 별도 승인 대기다.

## 사용 방법

메인 → **게임 추가** → 게임 이름 → 빈 구성 / KARDS 기본 구성 / 기존에 만든 게임의 규칙 복사 → 규칙 구성 → 저장.

등록한 게임의 **퀘스트·보상 규칙**에서 같은 편집기로 수정한다. 퀘스트·정기 수령을 추가하고, 규칙 복제·순서 이동·삭제, 갱신 주기·생성 수·상한·보상 선택·기수령 횟수를 설정할 수 있다. 추가 공급 활성 여부도 게임별로 지정한다. 빈 구성과 기본 항목 삭제를 허용한다.

## 구조 변경

- `syncCatalog(game, now)`, `completeCatalogRule(gameId, ...)`, `updateCatalog(gameId, rules)`, `runCatalogAction(gameId, ...)`로 실행 경로를 통합했다.
- 검증기에서 daily/free/chest 필수 조건을 제거했다. 새 규칙 생성은 게임별 프리셋을 참조하지 않는다.
- `renderCatalogGame(gameId)`와 `mountRuleEditor(...)`를 KARDS 및 사용자 게임에서 공유한다. 표시 선택은 규칙의 `view` 설정으로 결정한다. 기존 CSS·테스트 선택자 이름 일부는 호환성을 위해 남아 있으나 다른 게임에도 동일한 부품을 사용한다.
- KARDS 기존 필드·원장 키의 차이는 `catalogAdapter`로 격리했다. 이전 호출 이름은 공통 함수로 연결하는 얇은 호환 함수다. 이전 일일·무료·상자 기록을 다시 지급하지 않는다.
- 사용자 게임은 `state.customGames`에 등록하고 기존 v2의 `state.games[id]`에 정의·진행·원장을 보관한다. 외부 저장 키와 버전 변경은 없다. 등록 정보는 재시작 시 탐색 목록에 복원된다.
- 템플릿 복사는 진행·수령 기록을 복사하지 않는다. 규칙·퀘스트·보상에 새 ID를 발급하고 보상 참조를 재연결한다.
- 사용자 게임도 탭·메인·갱신·알림·음소거·개별 초기화·전체 초기화 경로에 포함된다. 개별 초기화는 이름을 유지하고 최초 설정으로 돌아간다.
- 생성·수정·보상 지급 실패 시 사본을 복원한다. 사용자 입력 이름은 HTML에 삽입할 때 이스케이프한다.

## 범위와 한계

이번 단계에서 범용화한 유형은 **quest와 claim**이다. 특정 목표(goal), 충전 자원, 패스, 연동 그래프 등은 아직 구현하지 않았다. 기존 8개 게임 전체가 범용 프리셋으로 전환되었다는 의미도 아니다. 후속 E1~E8에서 동일 엔진에 범용 기능을 추가하고 해당 게임을 프리셋으로 전환한다. 게임마다 전용 엔진을 복제하지 않는다.

설치 파일 목록을 변경하지 않도록 기존 로딩 파일 안에서 공통 처리와 호환 어댑터를 분리했다. 성능 향상률·소스 감소율은 이번 단계에서 측정하거나 주장하지 않는다.
