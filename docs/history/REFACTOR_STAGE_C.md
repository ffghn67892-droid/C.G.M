# C단계 결과 — 저장 확정과 보상 실행 경계

작성: 2026-09-18 KST  
상태: 완료. 다음 단계(D) 시작은 별도 사용자 승인이 필요하다.

## 변경

- `save()`는 먼저 전체 상태를 직렬화하고 `localStorage`에 기록한 뒤에만 마지막 확정 상태를 갱신한다.
- 직렬화 또는 저장이 실패하면 상태 루트 객체를 마지막 성공 저장본으로 되돌리고 예외를 전달한다. 따라서 진행도, 보상 원장, 누적 합계와 활동일이 저장본과 불일치한 상태로 남지 않는다.
- `commitStateChange()`를 공통 동작 확정 진입점으로 추가했다. 변경이 없으면 저장하지 않으며, 변경이 있으면 저장 성공 뒤에만 화면 성공 처리를 진행한다.
- KARDS 무료 카드와 50/60 GOLD 완료를 이 진입점으로 옮겼다. 저장 실패 시 저장 없는 현재 게임 렌더링과 오류 안내를 사용하므로 실패 중 재저장이 발생하지 않는다.
- 스냅 `renderSnapGame()`에서 주간 보상을 지급하던 호출을 제거했다. 주간 보상은 임무 완료나 최초 설정 같은 상태 변경 경로에서만 계산한다.

저장 스키마(v2), 저장 키, 기존 보상 원장 형식, 게임 규칙과 화면 배치는 바꾸지 않았다. 다른 기존 동작도 `save()`의 공통 복구 계약을 사용하므로 쓰기 실패 뒤 메모리 상태를 유지하지 않는다. 각 게임별 동작을 `commitStateChange()`로 명시적으로 이관하는 작업은 D와 E 단계에서 진행한다.

## 검증

- `tests/storage-commit.test.cjs`: KARDS 저장 실패 후 진행도·원장 롤백, 저장 복구 뒤 한 번 지급 및 재시도 확인.
- `tests/render-purity.test.cjs`: 스냅 화면 렌더링만으로 주간 보상이 지급되지 않음 확인.

공통 저장·보상 경로를 바꿨으므로 전체 테스트를 실행했다. UI 배치 변경과 설치 관련 변경은 없으므로 Electron 화면 검증, 패키지 빌드, 설치본 검증은 실행하지 않았다.
